**Phase 1 only · proposed for Claude review and owner approval · 2026-10-30.** No application code, test assertions, contracts or runtime data change in this PR. Phase 2 must wait for that review, explicit approval, and the backend deliveries identified below.

## 1. Proposed information architecture

Keep `/owner/evidence-hub` as the private entry point. Its title remains **مركز الأدلة / تحليلات مسارك**; English is **Evidence Hub / Your path insights**. Use two sections with real anchor navigation, enhanced into two tabs with JavaScript:

- **السجلات / Records**: up to three real recommendations, then project record cards, actual quality states and reasons, source counts, filters and record navigation.
- **تحليلات مسارك / Your path insights**: documentation coverage and confidence detail, maturity and progress, publication context, technology evidence and review, and skills without project evidence.

With JavaScript, one panel is visible at a time. Without JavaScript, both sections are present in document order, with native anchor links. Existing fragments `#next-steps`, `#overview`, `#project-evidence`, `#project-{id}`, `#technologies` and `#progress` remain meaningful. A direct fragment, validation failure or recommendation CTA opens the appropriate panel before focus moves. Tab changes use client state, not another authenticated request: they must not consume the immediate Undo opportunity. ARIA tabs are applied only when the tab interaction is actually enabled; native navigation remains navigation.

The reference's four-part reading/writing layout belongs to the existing private project evidence route, `/owner/projects/{id}/evidence`, using its authorized project text. Raw evidence must not be added to the hub model, a browser JSON payload or a public contract to make a reading overlay possible. The server view-mode request in §7 is needed for a safe native flow.

### Exact quality semantics to preserve

These are audited backend rules, **not proposed frontend validation**. Do not reimplement them in JavaScript or use textarea non-emptiness as their substitute. Three text-state segments and the `n/3` count refer to these evaluated fields; Sources has a count/absence state, not an invented quality grade or a fourth completeness point.

| Display part → existing field | Maximum Unicode scalars | Minimum effective content graphemes | Minimum useful tokens | Minimum distinct tokens |
| --- | ---: | ---: | ---: | ---: |
| السياق / Context → `problem` → `problem_statement` | 2000 | 60 | 8 | 5 |
| مساهمتي / Contribution → `personal_role` | 1500 | 30 | 5 | 4 |
| النتيجة / Result → `measurable_outcome` | 1000 | 20 | 4 | 3 |

- Missing reasons: `FIELD_NOT_AVAILABLE`, `EMPTY_NORMALIZED_VALUE`. Placeholder: `PLACEHOLDER_CONFIRMED`. The frozen placeholder vocabulary includes lorem ipsum variants, todo/tbd/coming soon/test/placeholder/n/a and the existing Arabic equivalents in `EvidenceTextPolicy::PLACEHOLDERS`; it is not expanded or loosened here.
- Detail reasons: `GRAPHEME_THRESHOLD_NOT_MET`, `USEFUL_TOKEN_THRESHOLD_NOT_MET`, `DISTINCT_TOKEN_THRESHOLD_NOT_MET`; repetition uses the existing dominant-token threshold (at least five useful tokens and at least 60% dominance).
- Live rules 1.1.0 collapse repeated letter runs of length at least three for effective content counting and exclude letter-only repeated-character tokens. `CHARACTER_RUN_SUSPECTED` explains a threshold lost by that adjustment. `LOW_DISTINCT_TOKEN_RATIO` uses at least 12 useful tokens and a distinct ratio below 40%.
- `DUPLICATED_ACROSS_FIELDS` compares only the three fields of the same project, using normalized equality or existing three-token shingle containment (at least three shingles, at least 80% containment) with the evaluator's field-order tie-break. Preserve its exact output; do not compare other owners/projects or send shingles to the client.
- Invalid reasons remain recoverable: `NON_SCALAR_INPUT`, `INVALID_UTF8`, `MAXIMUM_LENGTH_EXCEEDED`, `PROHIBITED_CONTROL_CHARACTER`, `ZERO_WIDTH_CHARACTER`, `PROHIBITED_DIRECTIONALITY_CHARACTER`. Storage-valid incomplete text may be saved; “Needs attention” is not automatically a rejected submission.
- Current cards receive one already-selected reason string per field. Preserve that explanation. If a design needs every simultaneous reason, request an explicit safe reason list from Claude; never retrieve raw internal evaluations/identities from elsewhere to fill it. The proposed first layer needs only the supplied primary reason.

## 5. Editor flow: Sources after save

**Choose “placing Sources after save.”** A JS-only dirty warning cannot guarantee native/no-JS safety, and the current evidence editor does not already have that guard. Combining the text and source fields in one POST would violate both contracts. Do not auto-save text, silently merge forms, intercept a source action and replay it after saving, or invent a successful save.

Proposed server modes on the existing project route, subject to B1:

1. **Read / Sources:** the canonical GET shows the four-part saved record. Parts 1–3 are read-only; their edit controls open a server-rendered Write mode for the chosen part. Source management is available in part 4 / `#sources`, with its own native forms. There are no editable text controls here, so Add/Remove cannot discard unsaved text. The source list/management can use native disclosure while keeping its direct fragment reachable.
2. **Write:** parts 1–3 remain one exact native form. With JS the stepper changes which field is visible, keeping all three controls in that form. Without JS they stack. The fourth step explains “Save the text first, then manage sources”; its action submits the existing text form, rather than navigating to a source form. Save works from every text part and may save incomplete, storage-valid text.
3. **Text save:** preserve the existing POST and 303 to `/owner/evidence-hub#project-{id}`. Show the actual saved/Undo feedback and the real Manage sources link. The owner can Undo immediately or continue to the canonical project route `#sources`. Continuing is another owner request and expires text Undo exactly as today; say so at that choice. Do not promise that source changes are undoable.
