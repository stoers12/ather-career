# Phase 2B — local account selection

**Scope:** Phase 2B is deployed on main at b8da333ca3346027eb4fc06d73785e77d5b367ed. The isolated fix/phase2b-switch-input-contract hotfix tightens request validation before any session transition. This local work does not change the canonical runtime, tenant, database, identity bindings, or provider sessions.

An authenticated Owner can choose **Use another account / استخدام حساب آخر** in either Owner navigation, including the no-Portfolio onboarding page. The button is a keyboard-operable POST form with the current session's CSRF token. The action validates the current active User, applies the existing OIDC start rate limit, and checks discovery before changing local authority. It then destroys the current Ather session, clears its session ID, creates and rotates a new anonymous session, and starts the existing state, nonce and PKCE S256 authorization-code flow with the single allowed optional `prompt=select_account`. The authorization endpoint must pass the existing HTTPS and configured-domain discovery checks. The switch route rejects query parameters and accepts exactly one scalar, non-empty csrf_token POST field; malformed or additional input receives a sanitized 403 before session retirement or OIDC transaction creation. No request-controlled return URL or authorization endpoint is accepted. Successful callbacks retain the fixed local Owner destinations.

Selecting a known account uses the Phase 2A exact issuer/subject binding and active-User checks. A selected identity with no binding, a conflicting binding, or a disabled User is denied before session establishment. A successful callback rotates the session again and derives Portfolio access from the authenticated User's current ownership row. Selecting the original account again follows the same path. The other browser's local session is independent. Back-button use of the retired local session, callback replay, and expired transactions fail closed.

An exact `access_denied` response with valid state and shape consumes the one-time transaction and is classified as cancellation or denial. The callback destroys the anonymous transaction session, rotates into a fresh anonymous session, and renders a no-store bilingual recovery page. It states that sign-in was not completed, the user is signed out, and no data changed. Its primary action is a CSRF-protected POST to `/owner_auth_retry.php`; the retry rejects extra query and form fields, rotates the anonymous session again, and starts a completely new state, nonce and PKCE transaction with `prompt=select_account`. The authorization endpoint comes only from validated issuer discovery, and the callback URI comes only from runtime configuration. The secondary `/owner_login.php` link is fixed and same-origin. Neither action silently restores the retired authenticated session. The recovery page requires no JavaScript and places keyboard focus on the primary action.

Invalid state, replay, expiry, malformed callbacks, identity conflicts, and unexpected provider errors use the sanitized failure wording on the same recovery page. They are never classified as ordinary cancellation. Provider descriptions, query values, identities, session IDs, and tokens are never reflected. A second cancellation returns to recovery without an automatic retry loop.

This action does **not** call a Google, Microsoft, or Auth0 logout endpoint. It cannot guarantee which accounts the provider displays; the provider's own signed-in state remains under provider control. It does not register, create, link, merge, repair, or consolidate users or identities. It changes no migration or protected data. The Owner interface explicitly advises switching before creating a Portfolio when the wrong account was selected.

Focused static and isolated synthetic rehearsals cover the POST/CSRF boundary, fixed prompt, bilingual control and recovery, wrong-account switch, two browser sessions, return to the original owner, cancellation and denial, repeated cancellation without loops, malformed and unexpected errors, replay, expired transaction, unknown and cross-owner identities, local session retirement, callback rotation, and no account or Portfolio count change. The existing Phase 2, security, production smoke, syntax, documentation, and cleanup gates must pass before local review commits. A live Auth0 account chooser test requires separate owner authorization after review.
