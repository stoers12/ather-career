# Phase 2B — local account selection

**Scope:** isolated review branch `feat/phase2b-account-selection`, based on the accepted Phase 2A merge `e1cd58d41d9996d3a97df425e9fd098d98258fbb`. This work does not change the canonical runtime, tenant, database, identity bindings, or provider sessions.

An authenticated Owner can choose **Use another account / استخدام حساب آخر** in either Owner navigation, including the no-Portfolio onboarding page. The button is a keyboard-operable POST form with the current session's CSRF token. The action validates the current active User, applies the existing OIDC start rate limit, and checks discovery before changing local authority. It then destroys the current Ather session, clears its session ID, creates and rotates a new anonymous session, and starts the existing state, nonce and PKCE S256 authorization-code flow with the single allowed optional `prompt=select_account`. The authorization endpoint must pass the existing HTTPS and configured-domain discovery checks. No request-controlled return URL is accepted. The callback and its fixed local Owner destinations are unchanged.

Selecting a known account uses the Phase 2A exact issuer/subject binding and active-User checks. A selected identity with no binding, a conflicting binding, or a disabled User is denied before session establishment. A successful callback rotates the session again and derives Portfolio access from the authenticated User's current ownership row. Selecting the original account again follows the same path. The other browser's local session is independent. Provider cancellation consumes the one-time transaction and leaves no authenticated Ather session. Back-button use of the retired local session, callback replay, and expired transactions fail closed.

This action does **not** call a Google, Microsoft, or Auth0 logout endpoint. It cannot guarantee which accounts the provider displays; the provider's own signed-in state remains under provider control. It does not register, create, link, merge, repair, or consolidate users or identities. It changes no migration or protected data. The Owner interface explicitly advises switching before creating a Portfolio when the wrong account was selected.

Focused static and isolated synthetic rehearsals cover the POST/CSRF boundary, fixed prompt, bilingual control, wrong-account switch, two browser sessions, return to the original owner, cancellation, replay, expired transaction, unknown and cross-owner identities, local session retirement, callback rotation, and no account or Portfolio count change. The existing Phase 2, security, production smoke, syntax, documentation, and cleanup gates must pass before local review commits. A live Auth0 account chooser test requires separate owner authorization after review.
